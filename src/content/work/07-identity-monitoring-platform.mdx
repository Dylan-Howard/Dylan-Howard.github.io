- **Problem:** Provisioning kept accounts flowing, but nothing showed where the systems disagreed. Every account-access ticket meant checking several admin consoles by hand.
- **What I built:** A control plane that reads each system's view of a person through APIs and databases every four hours, flags orphaned, duplicate, and mismatched records, and can disable, merge, or reset accounts.
- **Result:** After it launched in May 2024, account-access ticket resolution fell from **1.5 days to 0.6** (ticket export, May 2024 – May 2026). It also surfaced accounts nobody had looked at in years.

</div>

Provisioning is about making accounts. Nobody budgets for the accounts it leaves behind.

A sync can be correct every minute of every day and still leave a district full of quiet problems: an account kept alive as a favor, an email alias added in one system but not the other, a record entered twice. None of these break anything, so none of them file a ticket. I built the control plane to find them, and then to fix them without opening five admin consoles.

## Seeing It

The control plane reads each connected system's view of a person, through APIs where a system has one and databases where it doesn't. It runs every four hours. Each run logs what changed, and I keep the full sync files for ten days, so I can replay any run when I need to know what a system believed on a given afternoon.

The first version was a prototype in Java and Spring Boot, with a React and Astro frontend. Its early findings were real:

- **847 grade-level mismatches** between the student information system and the LMS. I admit I can no longer tell you the root cause.
- **1,200+ phone numbers** that failed a format check, traced to a free-text field in the legacy student system
- **43 staff accounts** whose Active Directory and Google email addresses had diverged, each because an alias was added in one system and never in the other

## Rebuilding It

I rebuilt the prototype in .NET, Entity Framework, and Next.js. The reason wasn't technical. Around Nashville and southern Kentucky, far more developers work in .NET than in Spring, and a tool the district depends on should be one the next person here can maintain.

## Acting on It

Finding a problem is only half of it. From the control plane I can disable an account, merge duplicates, or reset a password, and every one of those actions asks for confirmation first.

Some problems aren't mine to fix. A duplicate in the HR or student system is a legal record, and it can't change without documentation. For those, I messaged the data entry staff who own the record, so they could fix it with documentation.

## What It Found

The story I tell most is an account kept open for a senior employee after they left, so they could help with the transition. Nobody closed it afterward. For four years, an account with a lot of permissions sat there with no one managing it.

It wasn't the only one. The control plane surfaced several former employees who still had access to sensitive records, some without MFA. None of these accounts were broken. That's exactly why nothing else had caught them.

## Who It Served

I was the control plane's only user, so it's fair to ask how it helped anyone else. Account-access tickets still went back to the technicians who owned them. What changed was the round trip in the middle. When a ticket reached me, I could see every system's view of that person in one place and switch into the problem quickly, instead of gathering data and trading messages. The technician got an answer sooner, and so did the person locked out.
